# AeroVolt × 패브릭덕트

동남아시아 HVAC 시공업체를 발굴·검증하고, 검증 워크북 기준으로 채점·등급화해서
컨택 우선순위를 정하는 대시보드입니다. 2026 아임인부산 임팩트 해커톤 팀 AeroVolt,
담당 기업 패브릭덕트를 위해 만들었습니다.

## 실행 방법

```bash
npm install
npm run dev
```

## 데이터 소스

`src/config.js`의 `DATA_SOURCE`로 전환합니다.

- `"mock"` — 내장 샘플 데이터(오프라인에서도 동작)
- `"sheets"` — Google Sheets(업체 기본정보)를 실시간으로 불러와서, 이미 채점된 업체는
  `src/data/mockPartners.json`의 점수·등급과 자동으로 매칭합니다. 시트 연동에 필요한
  Apps Script는 `apps-script/Code.gs`를 참고하세요.

검증 점수·컨택 상태·비고는 항상 대시보드 안에서만 관리되며(새로고침 시 초기화),
Google Sheets에는 쓰지 않습니다.

## 메일 발송 콘솔

상단 탭 오른쪽 **`메일 발송`** 버튼(배지 = A·B 등급 + 15점 이상 후보 수)으로 모달을 엽니다.
심사표의 점수·등급을 그대로 이어받아 발송 대상을 고르고, 이메일·담당자를 표에서 직접 입력합니다.

- **연락처 입력** — 세 가지 경로가 있고, 우선순위는 아래와 같습니다.
  1. **구글 시트의 이메일 열** — 팀이 같이 채우는 공용 출처. 시트 `업체리스트` 탭에 헤더가
     `이메일`(또는 `메일`·`email`)인 열을 두면 자동으로 읽어옵니다. 헤더가 없으면 **M열**을
     보되, 값에 `@`가 있는 경우에만 이메일 열로 인정합니다. `담당자` 열도 같은 방식입니다.
  2. **표에서 직접 입력** — 시트 값 위에 덮어쓰는 이 브라우저만의 수정입니다. 엔터를 치면
     저장 후 다음 행의 같은 칸으로 넘어갑니다.
  3. **일괄 붙여넣기** — `업체명, 이메일, 담당자` (탭·쉼표·세미콜론 구분)

  표에서 한 번이라도 고친 칸은 **시트 값보다 우선**합니다(빈칸으로 지운 것도 유지). 시트를
  고쳐도 그 칸은 안 바뀌므로, 시트 값을 다시 쓰고 싶으면 그 칸을 지웠다가 새로고침하세요.
  ⚠️ 대시보드는 시트에 **쓰지 않습니다** — 표에서 입력한 주소는 시트로 올라가지 않습니다.
- **저장** — 입력 즉시 `localStorage`, 0.9초 뒤 아티팩트 `db`. 서버 값이 로컬 값을 덮어쓰지 않으며,
  표 입력칸에 포커스가 있는 동안에는 표를 다시 그리지 않습니다(입력 중 값·포커스 유실 방지).
- **템플릿** — 여러 개를 번호로 저장해두고 고릅니다. 표의 `템플릿` 열에서 행별로 다른 번호를
  지정할 수 있어 시공사·유통사에 다른 내용을 한 번에 보낼 수 있습니다.
- **치환** — `{{상호}} {{담당자}} {{국가}} {{지역}} {{유형}} {{총점}} {{등급}} {{국가(한글)}}`.
  본문이 영문이므로 국가·지역·유형은 영문으로 변환됩니다(베트남 → Vietnam, 하노이 → Hanoi).
  CSV도 같은 규칙으로 내보내므로 시트 메일머지에서도 한글이 섞이지 않습니다.
- **발송** — CSV 저장 / 클립보드 복사는 어디서나 동작합니다. 실제 발송은 아래 두 경로 중
  가능한 쪽이 자동으로 선택됩니다.

### 발송 경로

| 환경 | 경로 | 준비 |
|---|---|---|
| 배포된 홈페이지(GitHub Pages 등) | Apps Script 웹앱 → 스크립트 소유자의 Gmail | 아래 설정 필요 |
| Claude 아티팩트 + Gmail 커넥터 | Gmail 커넥터 직접 호출 | `mcp` capability 선언 |
| 둘 다 없을 때 | CSV만 | — |

## Apps Script 배포 (업체 목록 + 메일 발송)

업체 목록 조회(`doGet`)와 메일 발송(`doPost`)이 **웹 앱 배포 하나**를 같이 씁니다.

### 1. 코드 붙여넣기

구글 시트 > 확장 프로그램 > Apps Script 를 열고 [apps-script/Code.gs](apps-script/Code.gs)의
**전체 내용**을 붙여넣습니다.

### 2. 발송 키 정하기

`setUpMailer()` 안의 `SEND_KEY`를 아무도 모를 값으로 고친 뒤, 편집기 상단에서 그 함수를 골라
**한 번 실행**합니다. 권한 승인 창이 뜨면 본인 계정으로 승인합니다.
(`SENDER_NAME`·`REPLY_TO`·`DAILY_CAP`은 선택 사항)

### 3. 웹 앱으로 배포 — 액세스 권한이 핵심입니다

**배포 > 새 배포 > 유형 선택(톱니) > 웹 앱**

| 항목 | 값 |
|---|---|
| 다음 사용자 인증 정보로 실행 | **나** |
| 액세스 권한이 있는 사용자 | **모든 사용자** |

> `모든 사용자`가 아니면 구글이 **로그인 페이지로 리다이렉트**합니다. 그 응답에는 CORS 헤더가
> 없어서 브라우저가 요청을 막고, 대시보드에는 "연결하지 못했습니다"만 뜹니다. **"Google 계정이
> 있는 모든 사용자"도 로그인을 요구하므로 안 됩니다.** 반드시 `모든 사용자`여야 합니다.
>
> 발송 키를 요구하는 이유가 이것입니다 — 엔드포인트 자체는 공개일 수밖에 없습니다.

#### "모든 사용자" 옵션이 안 보인다면

**학교·회사(Google Workspace) 계정**은 관리자 정책으로 외부 공개가 막혀 있어 이 옵션이 아예
표시되지 않습니다. 목록에 `나만`과 `<도메인> 내 모든 사용자`만 보인다면 이 경우입니다.
(개인 Gmail 계정에는 항상 세 번째 옵션이 있습니다)

먼저 이것부터 확인하세요.

1. **배포 유형이 "웹 앱"인가** — 배포 대화상자의 톱니바퀴에서 `웹 앱`을 골라야 이 설정이
   나옵니다. `라이브러리`나 `API 실행 파일`을 고르면 다른 설정이 뜹니다.
2. **어떤 계정으로 열려 있는가** — 편집기 오른쪽 위 프로필. 학교·회사 도메인이면 위 사례입니다.

Workspace 계정이 원인이라면 **개인 Gmail 계정으로 스크립트만 옮기면** 됩니다. 팀 시트는 그대로
두고 읽기만 해오는 방식이라 데이터가 갈라지지 않습니다.

1. 개인 Gmail로 로그인해 [script.google.com](https://script.google.com) > **새 프로젝트**
2. [apps-script/Code.gs](apps-script/Code.gs) 전체를 붙여넣기
3. 맨 위 `SPREADSHEET_ID`에 팀 시트의 ID를 적기
   (`https://docs.google.com/spreadsheets/d/`**`여기가 ID`**`/edit`)
4. 팀 시트를 그 개인 계정에 공유 — 읽기만 하므로 **뷰어** 권한으로 충분합니다
5. `setUpMailer()` 실행 → 권한 승인 → `checkSetup()` 실행해 로그 확인
6. 위 3~5단계대로 **웹 앱** 배포 (이제 `모든 사용자`가 보입니다)

이렇게 하면 메일도 그 **개인 Gmail 주소로 발송되고 회신도 그리로 옵니다** — 대외 컨택용으로는
학교 주소보다 이쪽이 대체로 낫습니다.

> 설정이 맞는지 편집기에서 바로 보려면 **`checkSetup()`** 을 실행하고 하단 "실행 로그"를
> 확인하세요. 시트 접근·발송 키·발송 계정·남은 할당량을 한 번에 알려줍니다.

### 4. 배포 URL 확인

배포 후 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사합니다.

- ✅ 쓰는 것: **웹 앱 URL** — `/macros/s/.../exec`
- ❌ 쓰지 않는 것: **라이브러리 URL** — `/macros/library/d/.../3`
  (다른 스크립트가 이 코드를 함수로 가져다 쓸 때의 주소라 웹 요청을 못 받습니다)
- ❌ 쓰지 않는 것: `/dev`로 끝나는 테스트 URL (본인만 접근 가능)

**브라우저 주소창에 그 URL을 직접 붙여넣어 보세요.**

- 업체 목록 **JSON**이 보이면 → 정상
- **로그인 화면**이 뜨면 → 3번의 액세스 권한이 `모든 사용자`가 아님
- **오류 페이지**가 뜨면 → 편집기에서 `doGet`을 실행해 오류 메시지 확인

### 5. 대시보드에 주소 넣기

[src/config.js](src/config.js)의 `SHEETS_API_URL`에 넣고 다시 빌드하거나, 배포된 사이트에서
연결 배너의 **주소 바꾸기**에 붙여넣습니다(그 브라우저에만 저장되므로 확정 후 `config.js`에도
반영하세요).

### 6. 발송 연결 확인

메일 발송 > **발송 계정 연결**에 2번의 키를 넣고 `연결 확인` → 발송 계정과 남은 할당량이 뜨면
연결된 것입니다. `테스트 1건`으로 본인 주소에 먼저 보내 치환·서명·수신 상태를 확인한 뒤 전체
발송하세요.

메일은 **스크립트 소유자의 Gmail 계정에서 나가고, 회신도 그 계정으로 옵니다.** Gmail 무료
계정은 하루 약 100건, Workspace는 약 1,500건까지 보낼 수 있습니다.

### 코드를 고친 뒤 다시 배포할 때

**배포 > 배포 관리 > 편집(연필) > 버전 "새 버전" > 배포** — 이렇게 하면 **URL이 유지**됩니다.
"새 배포"를 누르면 항상 새 URL이 발급되므로 `config.js`도 함께 고쳐야 합니다.

> 시트에 연결하지 못하면 대시보드는 멈추지 않고 **내장 데이터(119개사)로 내려앉고** 상단에
> 이유를 띄웁니다. 채점·등급·메일 발송은 그대로 쓸 수 있고, 시트에서 새로 추가·수정한 업체
> 정보만 반영되지 않습니다.

## 배포

```bash
npm run build           # 일반 배포용(GitHub Pages 등)
npm run build:artifact  # 공유용 단일 HTML 파일 번들(dist-artifact/)
```

### 아티팩트로 게시할 때

`dist-artifact/index.html`을 Claude 아티팩트로 올릴 때 아래 capability를 선언하면
서버 저장(db)·CSV 다운로드·Gmail 발송이 모두 켜집니다.

```json
{
  "db": {},
  "downloads": true,
  "mcp": { "servers": [{ "server": "Gmail", "tools": ["create_draft", "send_message"] }] }
}
```

⚠️ **`mcp`를 선언하면 그 아티팩트는 외부 공개 공유가 막힙니다.** 팀 밖에 공유할 계획이라면
`mcp`를 빼고 게시하세요 — Gmail 버튼만 사라지고 나머지(입력·저장·템플릿·CSV)는 그대로 동작합니다.
capability 없이 올려도(또는 GitHub Pages에서도) 입력값은 브라우저 `localStorage`에 저장되고
CSV는 일반 다운로드로 내려받습니다.
